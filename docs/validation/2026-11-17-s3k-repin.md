# S3K driver re-pin and catalogue playback

The Deck is pinned to OpenGGF
`f3175b2225ad3b15be40d9075a7bb6a4dbeae4ca`. The fix covers wrapped durations,
HOLD and note fill, FM6 panning and DAC tail playback, voice initialization,
and native PSG and modulation envelope processing. The previous pin's
catalogue check found 28 blocked IDs. [OpenGGF PR #355](https://github.com/OpenGGF/OpenGGF/pull/355) · [Initial catalogue report](2026-11-17-native-import-target.md)

## Locked-on music catalogue

The local combined S3&K ROM matched SHA-1
`cfbf98c36c776677290a872547ac47c53d2761d6`. The read-only probe used the
OpenGGF loader for bank addresses, global voices, envelope playback views
and DAC resources. For each bank, it inferred the minimum local voice table
extent from the reachable voice selections. The build used the shaded Deck
JAR and the loader compiled from the pinned OpenGGF source.

| Strict preflight with cue context | 51 of 51 IDs passed, with 50 distinct headers |

| Previous-song cue | ID `2A` rendered with ID `05` warmed up for 120 presentations. The warm-up was excluded from output |

The aggregate SHA-256 for the signed 16-bit little-endian stereo PCM, in
ascending music ID order, was
`05142468a31c07e7e2ba4683641aa9300c187c2534f0e67e8aee2f254759cca3`.
The probe wrote counts and hashes only. The six-second runs cover successful
playback startup and the 1-Up restore path. Whole-song console PCM and
chip-write parity remain unverified.

  tests passed. Independent upstream and vendored synthesis produced the

  `acc6a3d5f35d293356edf1efb08401734348b41f2eb2b673e1a7c01128100451`.
